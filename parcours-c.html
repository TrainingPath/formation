🔧 Parcours C

Le langage système par excellence : pointeurs, mémoire, compilation — comprendre ce que les autres langages cachent.

Toutes les formations de la pile C, dans l'ordre conseillé — huit étapes, un fil rouge : la Ludothèque.

Légende : 🎯 cœur du bachelier (à faire en priorité) · 🧭 optionnel · plus tard (utile mais non essentiel dans l'immédiat). La durée indiquée par étape est une estimation à une leçon par jour.

🧠 Étape 1 — Les fondations : l'algorithmique · ~31 leçons

La logique avant le code, en pseudocode. Le socle de tout le parcours — et C plus qu'aucun autre en profite.

🧠

Algorithmique

La logique avant le code : variables, conditions, boucles, tableaux, fonctions, tris, récursivité, complexité.

Le langage C

Le langage système de référence : types et compilation, conditions et boucles, tableaux et fonctions, chaînes, pointeurs, allocation dynamique (malloc/free), structures, fichiers, préprocesseur et gestion mémoire.

🚀 Étape 3 — L'API et le rôle du C · ~21 leçons

Contrairement aux piles web (Java, PHP, Python, C#), le C n'utilise pas de framework web « batteries incluses » : c'est un langage système, employé au niveau bas (services, moteurs, embarqué). La conception d'API REST reste toutefois une culture transversale précieuse.

🔌

API REST

Le contrat entre un back-end et le reste du monde : HTTP, JSON, méthodes et codes de statut, conception des endpoints, pagination, erreurs propres, versions, OpenAPI, authentification (sessions, JWT), CORS et bonnes pratiques. Transversal à tous les langages.

21 leçons · fil rouge : l'API de la Ludothèque · prérequis : le langage C, notions réseau · 🎯 cœur du bachelier

✍️ 21 exercices d'écriture intégrés aux leçons

🗄️ Étape 4 — Les bases de données · ~63 leçons

La conception (Merise), le langage SQL, puis le SGBD. En C, on dialogue avec la base via son connecteur natif (par exemple l'API C de MySQL/MariaDB) en écrivant directement du SQL.

🧩

Merise (MCD, MLD)

La méthode de conception : entités, associations, cardinalités, héritage, contraintes ; puis passage au modèle relationnel (tables, clés) et au physique.

21 leçons · projet guidé : la base de la Ludothèque · prérequis : aucun · 🎯 cœur du bachelier

✍️ 21 exercices d'écriture intégrés aux leçons 📐

UML (les 14 diagrammes)

Le pendant objet de Merise : cadrer le besoin (cas d'utilisation), décrire la structure (classes), le comportement (séquence, états) et l'architecture. Même fil rouge : la Ludothèque.

31 jours · fil rouge : la Ludothèque · prérequis : aucun (Merise aide) · 🧭 optionnel · recommandé si ton école enseigne l'analyse

✍️ Un diagramme à produire par jour 🗃️

SQL (le langage)

Créer, remplir et interroger une base : SELECT, WHERE, jointures, agrégats, GROUP BY, sous-requêtes, vues, index, transactions.

21 leçons · projet guidé : interroger la Ludothèque · prérequis : Merise · 🎯 cœur du bachelier

✍️ 21 exercices d'écriture intégrés aux leçons 🐬

MySQL

Le SGBD open source le plus déployé : InnoDB, AUTO_INCREMENT, LIMIT/OFFSET, IFNULL, CTE et fenêtrage (MySQL 8), procédures (DELIMITER), triggers (NEW/OLD), transactions. Accessible en C via son connecteur natif.

21 leçons · projet guidé : la Ludothèque en MySQL · prérequis : SQL · 🧭 optionnel · plus tard

✍️ 21 exercices d'écriture intégrés aux leçons

🔗 Étape 5 — L'accès aux données (sans ORM)

Là où les autres piles utilisent un ORM (Hibernate, EF Core, Eloquent, Django), le C n'en a pas : on écrit le SQL directement et on mappe les résultats « à la main » dans des struct, via le connecteur C du SGBD (préparation des requêtes, liaison des paramètres, parcours des résultats). C'est plus verbeux, mais on comprend exactement ce qui se passe — l'esprit même du C.

🏗️ Étape 6 — Le projet full-stack (à la main) · ~21 leçons

La Ludothèque complète en C, de la conception à la mise en service, sans outillage.

Projet C · SQL · MySQL

Construire la Ludothèque de bout en bout en C : architecture en couches (UI → services → DAO → MySQL), modélisation en struct, accès MySQL via le connecteur C avec requêtes préparées, services métier (louer/acheter en transaction), rôles et authentification, gestion mémoire, tests et mise en service.

21 leçons · projet complet : la Ludothèque en C · prérequis : le langage C, Merise, SQL, MySQL · 🎯 cœur du bachelier

🧰 Étape 7 — L'outillage professionnel · ~94 leçons

Les outils transverses appliqués à ton projet : versionner, tester, conteneuriser, automatiser, sécuriser. (Le cours Linux, dans la catégorie Système, est un compagnon idéal pour la pile C.)

🌱

Git — les bases

Le contrôle de version de zéro : init, add, commit, status et diff, lire l'historique (log, show, HEAD), .gitignore, annuler proprement (restore, revert), tags et versions, découverte des branches, puis GitHub (clone, push, pull).

10 leçons · à suivre dès le Niveau 2 · prérequis : un terminal · 🎯 cœur du bachelier

✍️ 10 exercices d'écriture intégrés aux leçons 🧪

Tests & qualité logicielle

Écrire les tests que la CI exécutera : anatomie d'un test, fixtures, paramétrage, pyramide des tests, mocks, TDD, code legacy, couverture, tests d'intégration, lint, revue de code et refactoring. Concepts transposables aux frameworks de test C (Unity, Check).

21 leçons · fil rouge : tester la Ludothèque · prérequis : un langage du Niveau 2 · 🧭 optionnel · plus tard

Conteneuriser la Ludothèque de bout en bout : images et Dockerfile (multi-stage, non-root), volumes, réseau, Compose (healthchecks, limites), registre et versions, observation, déploiement en production et retour arrière.

21 leçons · fil rouge : la Ludothèque en conteneurs · prérequis : Linux, un capstone du Niveau 6 · 🧭 optionnel · plus tard

CI/CD & Git avancé

Automatiser la livraison de la Ludothèque : branches, pull requests et revue de code, pipeline GitHub Actions (build, tests, lint), protection de branche, versions semver, publication au registre, déploiement staging/production et rollback.

Sécurité applicative

Durcir la Ludothèque faille par faille : injection, XSS, CSRF, authentification et sessions, contrôle d'accès (IDOR), secrets, HTTPS, chiffrement, dépendances (CVE), en-têtes, DevSecOps, RGPD et réponse à incident. En C, la vigilance mémoire (dépassements de tampon) est centrale.
