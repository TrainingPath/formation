🌿 L'ORM de Django (Python)

Django est livré « batteries incluses », et la plus puissante de ses batteries est son ORM : le pont entre tes classes Python et tes tables MySQL. Tu écris Jeu.objects.filter(prix__lte=30), il écrit le SQL — mais un bon développeur sait exactement quel SQL il écrit, et pourquoi.

Chaque leçon : théorie · 15 exercices auto-corrigés · 1 exercice final · 1 exercice d'écriture. Le fil conducteur : la couche de persistance de la Ludothèque (jeux, membres, locations, avis), construite sur le schéma MySQL conçu au Niveau 4. Les équivalents Hibernate/JPA, EF Core et Eloquent sont signalés au fil des leçons.

Prérequis : le cours Django (Niveau 3), SQL et MySQL (Niveau 4). Le cours Django a fait effleurer models et migrations ; ici, on maîtrise l'ORM à fond, jusqu'aux transactions et au problème N+1 — le bagage attendu pour le projet full-stack du Niveau 6.

🛠️ Avant de commencer : préparer l'ORM de Django

1. Python et Django, déjà en place. Tu as Python 3.14 et un environnement virtuel (cours Python), et Django (cours Django). L'ORM est inclus dans Django — rien à installer de plus.

2. Une base de données. SQLite est fourni par défaut (aucune configuration, parfait pour apprendre). Pour du concret, PostgreSQL ou MySQL avec le connecteur Python correspondant (psycopg, mysqlclient), déclaré dans requirements.txt.

3. L'IDE. VS Code + l'extension « Python » (sélectionne l'interpréteur du venv) ou PyCharm. Les migrations se pilotent avec manage.py : python manage.py makemigrations puis migrate.

💡 Conseil : travaille dans un vrai projet Django branché sur ta base MySQL de la Ludothèque du Niveau 4, et garde python manage.py shell ouvert en permanence — dès la leçon 2, prends le réflexe print(qs.query) pour voir le SQL que l'ORM génère à ta place.
